F01 — P1 — Konten dokumen dapat membaca file lokal server
Source: app/knowledge/parser.py:18-25; app/api/routes.py:1332-1348;
        app/knowledge/rag.py (pemanggilan DocumentParser saat ingest).
TextParser mengubah string konten menjadi Path, lalu membaca file jika tersedia.
Endpoint publik /v1/documents/ingest meneruskan request.content sebagai source.
Tidak ada autentikasi atau pembatasan root pada jalur ini. Konten yang menyerupai
path absolut/relatif bisa memasukkan isi file yang dapat dibaca proses server ke RAG.
Dampak: kebocoran/penyalinan file lokal ke basis pengetahuan dan pencemaran sumber.
Reproduksi: DocumentParser mengembalikan isi file sementara dari input berupa path.
Keberhasilan ingest lengkap bergantung pada worker embedding dan database; belum diuji.
Perbaikan: pisahkan parsing konten literal dan impor file. Konten API harus selalu
literal; impor file harus membutuhkan autentikasi dan pemeriksaan workspace/sensitivitas.
Verifikasi: ingest string path harus menyimpan string itu, tidak membaca file; uji
path absolut, traversal, symlink, dan nama file sensitif dengan file contoh.

F03 — P1 — Pencarian pengetahuan gagal setelah retrieval
Source: app/api/routes.py:103 dan 1391-1403.
KnowledgeSearchRequest hanya memiliki query, top_k, filter. Fungsi search_knowledge
mengakses session_id/user_input dan gate_context/model_status/latency_ms yang tidak
didefinisikan di fungsi. Field ekstra request tidak memperbaiki kontrak schema ini.
Dampak: /v1/knowledge/search mengembalikan 500 setelah retrieval berhasil.
Reproduksi fungsi terisolasi dan pengujian API asli: 500, atribut session_id tidak ada. Variabel tak terdefinisi
akan tetap bermasalah jika hanya atribut request yang diperbaiki.
Perbaikan: hilangkan snapshot chat dari handler search atau bentuk konteks search yang
lengkap dan eksplisit. Pertahankan schema serta respons yang jelas.
Verifikasi: hasil kosong maupun hasil terisi harus berhasil pada endpoint asli.

F04 — P1 — Endpoint developer tidak memeriksa identitas pengguna
Source: app/api/v2_routes.py:159-175; app/main.py (registrasi router);
        docker-compose.yml:4.
/v2/dev membuka DevCore pada NUSANTARA_WORKSPACE atau cwd tanpa _require_admin,

Workspace mempunyai proteksi traversal/file sensitif, tetapi file source yang diizinkan

Perbaikan: wajibkan autentikasi/otorisasi developer; untuk penggunaan lokal batasi
publikasi port ke 127.0.0.1. Proteksi workspace tetap diperlukan.
Verifikasi: tanpa token atau token salah harus 401/403; pengguna berizin tetap berhasil.

F05 — P1 — Docker read-only tidak menyediakan penyimpanan writable aplikasi
Source: docker-compose.yml:9-10; app/knowledge/store.py:22-32;
        app/api/routes.py (KnowledgeEngine global); app/api/v2_routes.py:29-35.
Container API read_only:true hanya mempunyai tmpfs /tmp, tanpa volume data untuk API.
SQLiteVectorStore default membuat data/knowledge dan menginisialisasi DB saat
KnowledgeEngine dibuat pada import. Audit/experience juga menulis ke data/.
Volume pgdata milik PostgreSQL tidak dipasang ke API dan tidak menggantikan SQLite ini.
Dampak: dengan konfigurasi default, startup API berpotensi terhenti saat pembuatan
database; audit/persistensi tidak dapat ditulis. Temuan konfigurasi, belum diuji Docker.
Perbaikan: sediakan volume writable pada /app/data dengan pemilik yang sesuai, dan
selaraskan NUSANTARA_DATA_DIR/NUSANTARA_KNOWLEDGE_DB. Pertahankan root read-only.
Verifikasi: container start sehat, ingest/chat menulis data, restart mempertahankan data.

F06 — P2 — Healthcheck Docker merujuk file yang tidak ada dalam image
Source: Dockerfile:6-12.
HEALTHCHECK menjalankan python scripts/healthcheck.py, tetapi Dockerfile tidak menyalin
direktori scripts. COPY yang ada hanya app, docs, pyproject.toml, .env.example.
Dampak: healthcheck gagal meskipun API sudah bisa berjalan; status container unhealthy.
Perbaikan: salin skrip yang diperlukan atau gunakan pemeriksaan HTTP yang tersedia
langsung di image. Verifikasi melalui health status container yang benar-benar berjalan.

F07 — P1 — Jalur worker embedding default tidak tersedia pada Docker Linux
Source: app/language/semantic/indobert_client.py:27-39;
        app/knowledge/rag.py:220; Dockerfile:6-8.
RAG memakai IndoBERTEmbeddingAdapter secara default. IndoBERTClient memakai
nusantara-models/.venv/Scripts/python.exe dan nusantara-models/indobert_worker.py.
Image Linux tidak menyalin nusantara-models dan tidak memiliki interpreter Windows.
Dampak: ingest/retrieval yang membutuhkan embedding gagal, setelah masalah startup
penyimpanan diperbaiki. Environment Windows lengkap bisa berbeda.
Perbaikan: sediakan worker/model dan interpreter sesuai OS melalui konfigurasi,
atau jalankan worker sebagai layanan yang jelas kontraknya. Kegagalan harus terlihat
di readiness, bukan hanya health status ok.
Verifikasi: embed, ingest, retrieval semantik berhasil dari dalam container bersih.
