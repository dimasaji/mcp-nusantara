# MDE06 Embedding / Index Safety — design only

Decision: KEEP current database/index/embedding implementations and all data. EXTEND hard safety gate in a separately approved change; no gate code, rebuild, migration, model download or runtime activation is implemented in this audit.

Compatibility is an invocation/instance-scoped decision, not an inferred property of a model name. Before vector retrieval, compare an immutable descriptor of actual query embedding provider/model revision/dimension/normalization with the index descriptor: model/revision, dimension, float encoding/byte order, distance metric, generation/version and knowledge/source/chunk identity. Unknown mandatory identity must yield UNKNOWN and BLOCKED; observed mismatch INCOMPATIBLE and BLOCKED. Do not silently treat wrong-dimension empty hits or same-width foreign-model hits as compatibility proof.

Index states: CORRUPT for demonstrated structural/vector integrity violations; STALE for demonstrated source/content/generation mismatch; PARTIAL for uncovered intended chunks; INCOMPATIBLE for demonstrated profile mismatch; UNKNOWN when mandatory compatibility evidence absent; VALID only for the explicitly evidenced profile/generation/coverage scope. An overall state should preserve separate integrity, coverage, identity and compatibility findings. A healthy SQLite file is not a compatible index.

Canonical SQLiteVectorStore currently serializes little-endian float32 and searches by embedding_dimension, without query model/version filtering. Insert derives width from vector length rather than enforcing declared EmbeddingResult.dimension. Production bridge records model/version/dimension/text hash but uses native float32 encoding and model/version filters; dimension mismatch gives a cosine -1 sentinel rather than a hard block. Adapter validates 768 output but does not attest actual checkpoint revision. These behaviors are preserved during audit.

For production copied snapshot, 25 of 27 active chunks lack embedding rows for declared indobert-base-p1-v1; coverage is PARTIAL. The two existing rows match declared width/model/version and content hash, but actual model checkpoint/normalization identity, complete generation/version binding and deployed query compatibility are unverified. Canonical copied snapshot has five 768-dimensional rows but no immutable index/knowledge/model-generation binding; compatibility UNKNOWN. Block use under the proposed contract until proven. Do not falsely claim the existing runtime already implements this block.

## Concrete Level C proposal — not authorized or executed

Action: extend existing query/insert boundaries with explicit identity/dimension/encoding validation and compatibility outcomes; add descriptor/evidence contracts without creating a second vector store. Candidate files: app/knowledge/store.py, app/knowledge/schemas.py, app/knowledge/indobert_embedding.py, app/knowledge/production_embedding_bridge.py and approved assembly handoff in app/knowledge/rag.py. Exact schema/version descriptor representation needs owner review before migration. No database schema change is preapproved.

Reason: fixture observations prove width-only filtering and declared-width drift do not satisfy a hard compatibility gate. Impact: previously accepted vectors/queries may be rejected; unknown historical index identity must be handled explicitly. Risk HIGH for silent retrieval changes or invalid migration. Evidence needed: accepted model revision/encoding/distance descriptor, source and index generations, chunk coverage policy, expected fallback outcomes, fixture tests for equal-width foreign model and mismatched width, and separately approved deployed runtime checks.

Rollback prerequisites: capture/hash exact approved source patch and database artifacts (including WAL/SHM if relevant) before mutation; define migration-aware restoration separately. Current copied audit snapshots are evidence, not automatic production restore instructions. No rollback or production file deletion is executed here.

Rebuild proposal must be separate: define missing/stale set, source/model profile, generation, expected coverage, backup/restore, validation and explicit rebuild approval. Current APPROVE MDE-06 authorizes audit only and does not authorize filling missing embeddings, rebuilding production indexes or running embedding/search CLI.
