## Penyebab yang terbukti

1. **Penolakan chat umum.** Nama domain seperti KTP masuk guard evidence;
   jalur publik tidak mendapatkan dokumen internal. Saat model menghasilkan
   jawaban, guard menggantinya dengan penolakan Knowledge. Baseline nyata:
   sesi `web-b1d215e0-30aa-4633-843e-d03adf990bfd`, model `llama3.2:1b`,
   `reason=no_evidence`. Guard keluaran juga terlalu luas: kata “biaya” dalam
   uraian umum dapat menolak seluruh jawaban. Ini direproduksi lewat adapter Ollama.
2. **Konteks.** Jalur lama mengenali percakapan lewat allowlist dan kata rujukan
   terbatas. Pada uji nyata berikutnya, riwayat enam pesan juga membuat model
   menjawab `2+2` saat diminta menyederhanakan uraian KTP. Regresi itu direproduksi
   sebelum patch pemilihan konteks terakhir.
3. **Label verifikasi.** UI memakai `requires_human || !grounded` untuk semua
   jawaban. Assessment tanpa evidence dapat bernilai high/requires_human,
   termasuk sapaan/hitungan. Ketiadaan evidence bukan validasi dokumen resmi.
4. **Pesan gagal.** Angka UI berasal dari turn berstatus FAILED yang tersimpan.
   Pada uji tugas ini pertanyaan dokumen menghasilkan 504 dan FAILED.
   Penyebab historis “1 pesan gagal” milik sesi pengguna belum dapat dikorelasikan
   karena request/session asal tidak tersedia; tidak dianggap sama dengan kegagalan uji baru.
5. **Dokumen nyata.** Upload PDF asli mencapai DUPLICATE. Salinan uji dengan
   isi halaman sama dan metadata PDF berbeda mencapai pipeline baru, lalu
   ditolak `EMBEDDING_PROFILE_INCOMPATIBLE; no knowledge changed`.
   Endpoint Knowledge aktual mengonfirmasi konfigurasi 768 dimensi, tetapi
   indeks berisi satu chunk 16 dimensi dan 36 chunk 768 dimensi. Nama model
