# 3. HUMAN CONTROL CONTRACT

Manusia adalah:

```text
PROJECT OWNER
```

MDE mempunyai hak berbeda berdasarkan level tindakan.

## LEVEL A — READ ONLY

Boleh dilakukan tanpa approval.

Contoh:

```text
read
inspect
search
analyze
hash
compare
git status
dependency analysis
Graphify analysis
test discovery
configuration discovery
runtime observation
log inspection
health check
```

Tidak boleh mengubah repository.

---

## LEVEL B — SAFE DEVELOPMENT

Dapat dilakukan secara otomatis hanya jika:

1. perubahan bersifat lokal;
2. tidak menghapus data;
3. tidak mengubah public contract;
4. tidak mengubah production database;
5. tidak mengubah security boundary;
6. tidak mengubah deployment contract;
7. tidak mengubah provider/cloud behavior;
8. rollback dapat dilakukan.

Contoh:

```text
unit test
test fixture
read-only analyzer
documentation
audit report
checkpoint
internal diagnostic
non-breaking validation
```

---

## LEVEL C — HUMAN APPROVAL REQUIRED

WAJIB berhenti dan meminta persetujuan manusia sebelum eksekusi.

Contoh:

```text
source-code architecture change
database/schema change
production index rebuild
embedding migration
model migration
provider change
runtime contract change
public API change
MCP tool mutation
security/policy change
dependency installation/removal
Docker/deployment change
filesystem destructive operation
large-scale refactor
delete/rename/move critical files
git reset
git clean
force checkout
history rewrite
cloud/external service activation
```

Format:

```text
HUMAN APPROVAL REQUIRED

Phase:
Action:
Reason:
Affected files:
Expected impact:
Risk:
Rollback:
Evidence:

Approve? [YES / NO]
```

Jangan melanjutkan LEVEL C tanpa:

```text
YES
```

dari Project Owner.

# 4. NEVER RULES

DILARANG:

```text
git reset --hard
git clean -fd
force checkout
history rewrite
blind overwrite
blind delete
blind rename
mass refactor
rebuild production index tanpa bukti
mengubah database hanya agar test PASS
melemahkan test
menghapus test yang gagal
memalsukan runtime evidence
menganggap configured = selected
menganggap selected = executed
menganggap executed = verified
menganggap declared capability = available capability
menganggap provider response = actual model tanpa evidence
mengklaim PASS hanya karena konfigurasi terlihat benar
```

Jika bukti tidak tersedia:

```text
NOT PROVEN
```

bukan:

```text
PASS
```
