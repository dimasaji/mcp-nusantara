# Security and protected-state review

Browser requests can only call the new ATTESTATION-only intention adapter. Exact loopback peer, runtime Host 127.0.0.1:8000, allowlisted Origin (127.0.0.1:5173 or :8000), application/json, 512-byte bound, unique JSON keys and exact scope/evidence_version fields are required. Missing/null/other-port Origin is rejected. These guards are not Windows actor authentication; browser intentions remain untrusted PENDING.

Version validation and queue/audit creation use the private owner's RLock. Expected version is checked again against the exact material used to construct the binding before queue/audit mutation. Duplicate submissions reuse the original PENDING review and expiry, with no new audit or queue entry. Expired/terminal context cannot renew from this adapter. Memory is bounded; capacity rejection does not poison authority. Actual storage failures retain the existing fail-closed owner behavior.

No token, VerifiedPeer, arbitrary actor/reviewer claim, prompt, model override or client-selected expiry enters the adapter. Existing AuditTrail/ApprovalQueue remain private process-memory owners. Their classes, native peer authentication, decision transitions, permit transport and NORMAL owner were not modified. New adapter/helper functions are included in scoped loaded-code coverage. The manifest is non-transitive; it is not a full build proof.

The installed owner still receives no policy or transport. ARM/EXECUTE remain mechanically rejected after a trusted-peer unit seam, and untrusted browser actors are rejected before any decision. The unit seam is explicitly mocked; it does not claim native attribution or open IPC. No grant, dispatch, generation or policy provisioning occurs in these tests. Existing isolated positive ARM/EXECUTE tests were not run in this phase.

ATTESTATION never executes NORMAL project(), its protected-file digest path, production API owners, KnowledgeEngine, SQLite or sidecars. Guarded real app composition blocks protected imports, file writes/protected reads, SQLite connection, application socket connections, HTTP transports, provider health/model listing and LocalOperatorChannel activation. Windows asyncio's internal stdlib socketpair is allowed solely for the in-process test event loop; it is not an application HTTP listener. No live HTTP request was made.

Frontend schema rejects fabricated status promotion and unknown/mixed contract variants. NORMAL schema is preserved. Browser observation results and session-only historical receipts do not become server authority. Explicit intention is submitted once per reviewed presentation context, without automatic POST retry; responses must match scope/version and state PENDING. Evidence drift resets preparation; late responses for an obsolete context are not displayed as current.

Server review state remains a detached bounded projection. Its simple state summary is not a complete signed/durable decision receipt or native confirmation workflow. Provider receipt presence does not promote verification. JavaScript cannot exactly represent every Windows FILETIME integer; the UI explicitly labels this numeric projection's precision limitation. Authoritative version/binding checks use the server's original exact integer, not the browser's rendered number. No authorization semantic was changed to address browser precision.

No authorization/gate record was edited. All written source paths are listed in IMPLEMENTATION_MAP.md; SOURCE_COMPARISON.json checks monitored unrelated source stability. Database/sidecar integrity is deliberately not hashed or claimed. Same-account malicious clients can still consume the single pending intention for a context; this interface does not establish physical human presence or robust multi-operator availability. Native activation, broader lifecycle and live execution remain separate human gates.
