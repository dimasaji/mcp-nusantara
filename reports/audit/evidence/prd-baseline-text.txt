1. Ringkasan dan tujuan produk
NUSANTARA adalah Universal AI Workspace berbasis web dengan chat AI, pemrosesan dokumen, Knowledge/RAG, Tools & Skills, workflow dan Human Control. Implementasi V1 diuji pada SOP Disdukcapil; arsitektur tetap universal lintas OPD. Sasaran utama saat ini: satu alur upload PDF sampai jawaban bersitasi berhasil end-to-end, tanpa rebuild arsitektur.
2. Prinsip dan batasan
• Operator-first: navigasi sederhana; detail R1–R21 berada di backend/evidence.
• V1 ONLY: jangan mengembangkan fitur V2 atau studi kasus OPD lain.
• Governance validasi substantif dokumen resmi terverifikasi; keamanan sistem dasar tetap universal.
• Model lokal dan OpenRouter didukung; dokumen sensitif tidak otomatis dikirim ke provider eksternal.
• Status PASS hanya berdasarkan evidence aktual, bukan rencana atau mockup.
• Perbaiki modul yang ada terlebih dahulu; tidak mengganti backend dengan Open WebUI/Dify/n8n/Langflow.

6. Alur utama E2E (prioritas P0)
Upload PDF → ekstraksi Docling → review versi isi → approval operator → simpan dokumen → indexing → retrieval → chat SOP/chat utama → jawaban grounded dan sitasi → evidence dan status Control Plane.
Gate P0: satu dokumen SOP “Permohonan Data Pribadi” dapat melalui seluruh tahapan; uji pertanyaan persyaratan, prosedur, waktu, biaya bila ada, dan pertanyaan di luar sumber. Tidak boleh mengarang data yang tidak tercantum.
7. Insiden aktif per 26 Oktober 2026
Pada halaman Knowledge, dokumen “PERMOHONAN DATA PRIBADI” dilaporkan berstatus ekstraksi COMPLETE, tetapi pemeriksaan isi gagal HTTP 500. Persetujuan belum dapat diselesaikan; penyimpanan/indexing belum terbukti; Chat SOP dan Chat Utama belum PASS. Identitas dokumen berbasis SHA-256 dan versi isi perlu tetap konsisten selama perbaikan.
Prioritas debugging: trace request review → validasi token/otorisasi → backend exception → transaksi approval/persist → indexing → retrieval → UI state. Tidak mengubah IndoBERT atau mengganti arsitektur tanpa bukti akar masalah.

9. Nonfunctional requirements
• Reliability: alur normal tanpa HTTP 500; kegagalan mempunyai pesan dan trace.
• Integrity: approval terikat pada versi konten; persistensi dan indexing konsisten.
• Grounding: jawaban mengacu sumber; pertanyaan di luar sumber diakui.
• Usability: operator nonteknis dapat menyelesaikan workflow.
• Security: API key tidak bocor; data rahasia tidak keluar tanpa izin.
• Observability: log, status, biaya dan evidence bisa ditelusuri.
• Recoverability: backup/restore teruji sebelum deployment.
