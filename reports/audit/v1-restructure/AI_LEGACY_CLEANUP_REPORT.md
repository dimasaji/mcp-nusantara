## 2. What "AI legacy" means precisely

The contract forbids the vague instruction "clean up the AI files". This report defines the category operationally. A file is AI legacy if **all four** hold:

1. It is not imported, executed, or read by the V1 runtime.
2. It is not referenced by the official start/stop/status/doctor scripts.
3. It is not an audit artefact required to prove a V1 claim.
4. It was produced by an iterative AI session rather than by the product's own operation.

A file that fails only (3) — an old audit — is `KEEP-HISTORY`, not legacy.

### 6.2 Two classifier defects were found and fixed

Recorded here because an audit that hides its own corrections is worthless.

**Defect 1** — zero-byte files were evaluated before the KEEP-CRITICAL rule. `data\chat.db` is legitimately 0 bytes until first write, so it was flagged for deletion. Fixed by reordering. Effect: KEEP-CRITICAL 1,756 → **2,756**.

**Defect 2** — zero-byte disposal applied to every directory. `app\action\__init__.py` and ten sibling package markers are 0 bytes and load-bearing. Fixed by restricting disposal to the repository **root**. Effect: DELETE-CANDIDATE 1,660 → **12**.

Both defects would have caused real damage. Both were caught by asking "does this file have a legitimate reason to be empty?" rather than trusting the rule.

## 7. The `app\v2\` question — deferred, not dodged

The archive manifest lists 12 files under `app\`, of which 11 are `.backup*` copies and 3 are `.before_*_patch.py` snapshots. It does **not** list `app\v2\` or `app\api\v2_routes.py`.

That omission is deliberate, and the reasoning matters:

| Fact | Evidence |
|---|---|
| `app\v2\` is unreachable from the registered routers | `app\main.py:84-86` registers only `api_router`, `inspection_preview_router`, `control_plane_router` |
| A test enforces that it stays unreachable | `tests\test_v2_disabled.py:58` — `if name == 'app.api.v2_routes' or name.startswith('app.v2')` |
| Other tests still import it directly | `tests\test_fullroot_boundaries.py:14-15`, `tests\test_trace_retention.py:5` |

**Removing `app\v2\` would break 3 test modules**, including `test_fullroot_boundaries.py` which validates V1 boundary behaviour using V2 imports as fixtures. That makes the removal a test-suite change, not just a file move — and it would reduce coverage of a V1 security property.

**Ruling:** `app\v2\` and `app\api\v2_routes.py` are recorded as **ARCHIVE-CANDIDATE (deferred)** with a hard precondition: the three dependent test modules must be rewritten to not import V2 before any deletion. The precondition is not met, so nothing is proposed for action.

```powershell
# 1. Create destination
$dst = "C:\Users\dmaza\NUSANTARA_V1_ARCHIVE"
foreach ($b in 'historical-audits','superseded-contracts','old-ai-generated',
               'obsolete-experiments','legacy-reports') {
    New-Item -ItemType Directory -Force -Path "$dst\$b" | Out-Null

# 2. Copy with structure preserved (never move first)
$rows = Import-Csv "reports\audit\v1-restructure\FILE_ARCHIVE_MANIFEST.csv"
foreach ($r in $rows) {
    $target = Join-Path $dst ($r.archive_bucket + "\" + $r.path)

    Copy-Item -LiteralPath $r.path -Destination $target -Force
}

# 4. Only after verification: remove sources
```

**Copy → verify → remove.** Never move. The backup at `E:\NUSANTARA_BACKUP\02_source\` is the second copy during the operation, so no file is ever single-instance.
